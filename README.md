### “원래 그렇게 한다”는 말에서, 더 나은 방법을 찾습니다.

LLM 기반 에이전트와 데이터 분석을 활용해 실제 업무에 도움이 되는 서비스를 개발하고 있습니다.

멀티 에이전트 기반 개발 문서 자동화 플랫폼 **ALPLED**에서 **통합시험 시나리오 생성 에이전트 개발**을 담당했습니다.

**NeuroAge-MAS**에서는 뇌 체적·임상·유전체 자료의 입력 검증부터 모델 비교, 연구 결과 검토와 보고서 생성까지 연결하는 연구용 플랫폼을 개발하고 있습니다.

또한 **MedWatch PMS**를 통해 의료기기 시판 후 관리 업무를, **Brain MRI** 프로젝트를 통해 의료영상 로딩·마스크 처리·부피 계산·3D 시각화를 다루고 있습니다.

입력 데이터의 근거와 처리 과정을 확인하고, 결과를 재현하고 다시 검토할 수 있는 구조를 만드는 데 관심이 있습니다.

## 🤖 ALPLED

### 멀티 에이전트 기반 AI-DLC 문서 생성 자동화 플랫폼

**팀 프로젝트 · 담당: 통합시험 시나리오 생성 에이전트**

제안요청서와 회의록을 바탕으로 요구사항·설계·테스트 등 6종 소프트웨어 개발 산출물을 생성하는 플랫폼입니다.

반복적인 문서 작성을 자동화하고, 산출물 사이의 연결 관계와 정합성을 관리하는 프로젝트에 참여했습니다.

### 🎯 담당한 문제

요구사항을 시험 시나리오로 변환하는 과정에서는 요구사항 누락, 참조 정보 부족, 불완전한 JSON 응답, 시험 절차와 설명의 불일치가 발생할 수 있습니다.

이를 다루기 위해 다음 흐름의 `TestScenarioGenerationAgent`를 개발했습니다.

**입력 검증 → 단계별 생성 → 요구사항 연결 확인 → 출력 정규화 → 경고·오류 반환**

### 주요 구현

#### 입력 검증과 전처리

- 산출물 코드 `TS`와 실행 모드 검증
- `udt_yn`을 기준으로 신규 생성·수정 흐름 분리
- 요구사항·인터페이스 참조 정보의 필수 입력 확인
- 기능 요구사항 필터링과 LLM 전달용 입력 압축
- 필수 입력 누락 시 오류 코드와 실패 상태 반환

#### 단계별 생성 파이프라인

1. 기능 요구사항 기반 시험 시나리오 생성
2. 요구사항 ID 연결 누락 확인과 시나리오 보완
3. 시나리오별 테스트 케이스 생성
4. 시험 절차의 기본 단계 생성
5. 인터페이스 참조 기반 상세 절차 생성
6. 확정된 최종 절차를 기준으로 설명 요약 생성

상세 절차를 확정한 뒤 요약을 생성하여, 요약과 최종 시험 절차의 불일치를 줄이도록 구성했습니다.

#### 요구사항 추적

- `source_requirement_ids`로 원본 요구사항과 시나리오 연결
- 입력 요구사항과 생성 결과의 ID 비교
- 연결되지 않은 요구사항에 대한 시나리오 보완
- 보완 내용을 경고 정보로 기록
- 테스트 케이스까지 요구사항 추적 정보 전달

요구사항 ID 연결 여부와 시험 내용의 충분성은 구분하여 검토합니다.

#### 구조화 출력과 오류 대응

- 시나리오·케이스·절차·상세 정보를 JSON 목록으로 구성
- 공통 `LLMClient`와 병렬 호출 유틸리티 활용
- JSON 응답 파싱과 필드 자료형 정규화
- 호출·파싱 실패 시 기본 생성 로직 적용
- 경고와 오류를 구분해 후속 검토 지원
- 실제 시험 전 `test_result`를 `None`으로 유지

#### 공통 워크플로 연동

- `WorkflowState`에서 선행 에이전트 출력 참조
- `agent_outputs`에 생성 결과 저장
- 성공·실패 상태와 경고·오류 구분
- 기존 산출물 수정과 단계별 정제 흐름 구성

### 주요 출력

| 필드 | 내용 |
|---|---|
| `scenario_json_list` | 요구사항 기반 시험 시나리오 |
| `test_case_json_list` | 시나리오별 테스트 케이스 |
| `step_json_list` | 케이스별 시험 절차 |
| `step_detail_json_list` | 사전조건·입력값·예상결과·화면 ID |
| `warnings` | 누락 보완·기본값 적용 등 검토 정보 |
| `errors` | 처리 실패 관련 오류 정보 |

## 🧠 NeuroAge-MAS

### 뇌 체적·임상·유전체 데이터 연구 플랫폼

표 형식 뇌 부피·임상·유전체 자료의 입력 검증부터 분석 실행, 모델 비교, 내부 연구 검토와 보고서 생성까지 연결하는 연구용 플랫폼입니다.

**입력 검증 → 데이터 처리 → 분석·모델 비교 → 정합성 검사 → 내부 검토 → 보고서 생성**

### 🎯 해결하려는 문제

연구 데이터는 단위, 방문 시점, 결측 코드와 대상자 식별 기준이 서로 다를 수 있습니다.

입력 계약과 데이터 연결 근거를 확인하고 실행 설정과 결과를 기록하여, 분석 가능한 범위와 추가 확인이 필요한 부분을 함께 보여주는 구조를 개발하고 있습니다.

### 주요 기능

#### 1. 종단 뇌 체적 분석

- 대상자·방문·단위·시점의 입력 계약 검증
- ROI별 부피 변화량과 변화율 계산
- 시간 간격이 확인된 경우에만 연간 변화 환산
- 입력 근거와 분석 가능 범위 표시

#### 2. 임상 데이터 처리

- 코드북 기반 변수 처리
- 특수 결측 코드 관리
- 교육용 임상 자료에서 당뇨 첫 확인 조사일 분석
- 데이터 간 연결 근거와 해석 범위 표시

#### 3. 모델 비교와 멀티모달 실험

- 표형 특징 기반 회귀·분류 모델 비교
- 환자 단위 데이터 분할
- 학습 fold 내부 전처리를 통한 데이터 누수 방지
- 교차검증과 선택적 하이퍼파라미터 탐색
- 조기 결합·고정 가중치 결합·OOF 기반 stacking
- Permutation importance와 선택적 SHAP 분석

| 구분 | 모델·방법 |
|---|---|
| 회귀 | Dummy baseline · Ridge · ElasticNet · Random Forest · SVR · XGBoost |
| 분류 | Logistic Regression · Random Forest · XGBoost |
| 모델 선택 | 환자 단위 분할 · 교차검증 · 선택적 Optuna |
| 결합 | 조기 결합 · 고정 가중치 결합 · OOF stacking |

#### 4. 불확실성과 분포 점검

- Bootstrap 기반 추정
- Conformal prediction interval
- 데이터 drift 점검
- 메타데이터 조건을 충족한 경우의 neuroHarmonize ComBat 연계

#### 5. 유전체 연계

- PLINK BED·BIM·FAM 구조 검사
- QC·PCA·PRS·GWAS 실행 래퍼
- 유전 PC·PRS의 출처 확인
- 유전체 빌드와 대상자 연결 검사

PLINK 분석에는 별도 실행 파일과 검증된 입력·대상자 매핑·가중치가 필요합니다.

#### 6. 근거 검색과 연구 이력

- TF-IDF와 cosine similarity 기반 관련 문서 발췌 검색
- 출처·페이지 정보를 포함한 검색 결과
- 역할별 Python 에이전트와 산출물 오케스트레이션
- 입력·설정·모델·결과의 해시 기록
- 분석 실행과 정합성 검사 상태 분리
- 내부 연구 검토·승인 이력 관리
- PDF·DOCX·HTML·Markdown·CSV·JSON 결과 출력

<details>
<summary><b>선택적 실험과 결과 해석 범위</b></summary>

- SHAP·Optuna·ComBat·PyTorch 실험은 의존성과 설정 조건에 따라 사용합니다.
- PyTorch MLP와 CPU 기반 FedAvg는 선택적 실험 경로입니다.
- FedAvg는 로컬 시뮬레이션이며 실제 병원 간 연합학습을 의미하지 않습니다.
- Redis는 선택적 알림 용도로 구분합니다.
- 외부 LLM 설명 연동과 PostgreSQL 기반 분산 운영은 현재 구현 범위와 구분합니다.
- 원본 MRI의 분할·정합과 3D CNN 학습은 현재 플랫폼 범위에 포함하지 않습니다.
- 뇌 나이 실험은 실제 나이 라벨·촬영 시점·입력 근거를 충족해야 하는 별도 경로입니다.
- 합성 자료·교육용 자료·실제 자료를 구분합니다.
- 합성 실험 결과를 실제 환자 성능이나 의료적 효과로 해석하지 않습니다.

## 🏥 MedWatch PMS

### 의료기기 시판 후 안전관리·리콜 업무 지원 시스템

[![Repository](https://img.shields.io/badge/GitHub-medical--divice--pms-181717?style=flat-square&logo=github)](https://github.com/junhaj27-jpg/medical-divice-pms)

의료기기 출시 후 발생하는 고객 불만, 이상사례, 위험평가, CAPA, 규제보고 검토와 리콜을 사건 단위로 연결하는 RA·QA 포트폴리오 프로젝트입니다.

**불만 접수 → 이상사례 판단 → 위험평가 → CAPA → 규제보고 검토 → 리콜 검토 → 승인 → 조치 완료·종료**

### 🎯 해결하려는 문제

업무가 개별 기록으로 분리되면 담당자, 판단 근거, 승인 당시 자료와 후속 조치를 함께 확인하기 어렵습니다.

이를 사건 중심으로 연결하고, 누가 어떤 자료를 근거로 판단했는지 추적할 수 있는 업무 흐름을 구현하고 있습니다.

### 주요 개발 내용

#### 1. 업무 상태와 접근 권한

- 단계별 상태 전이와 선행조건 검증
- STAFF·RA_QA·ADMIN 역할별 업무 범위 구분
- STAFF의 본인 접수 사건 조회 제한
- 화면·API의 객체 접근 권한 검사
- 담당자·기한·개인별 할 일·알림 관리

#### 2. 위험평가와 CAPA

- 심각도와 발생 가능성에 따른 위험점수·등급 계산
- 제품·LOT 기준 반복 불만 탐지
- 고위험 사건의 CAPA 등록 선행조건 검증
- 원인 분석, 시정·예방조치와 증빙 관리
- 효과성 평가 이력과 미흡 시 재조치 연결

위험등급과 탐지 기준은 시연용 내부 규칙으로 구분합니다.

#### 3. 리콜 회수 관리

- 제품·UDI·LOT·시리얼 추적
- 거래처별 통보·회신·부분 회수 이력
- 회수 수량 검증과 회수율 계산
- 미회수 사유와 후속 연락 기록
- 승인·반려와 종료 보고서 출력

#### 4. 규정 근거와 보고 규칙

- PDF·TXT 규정 문서의 출처·버전·시행일 관리
- 페이지·절·문단 단위 로컬 근거 검색
- 규칙 항목별 원문 인용과 담당자 해석 연결
- 초안·검토·승인·시행·폐기 상태 관리
- 작성자와 승인자 분리
- 규칙 버전 비교와 변경 이력 보존
- 기한 계산 미리보기와 사건별 명시적 적용
- 적용 당시 규칙·입력·계산 결과 스냅샷

#### 5. RA 도우미와 추적성

- 접근 가능한 사건의 상태·고위험·기한 초과 현황 조회

- 사용자별 대화 분리와 직접 식별정보 입력 차단
- 승인 요청 시점의 자료 스냅샷
- 주요 업무 감사 로그
- 증빙 파일 검사 상태에 따른 접근 제한
- 서버 PDF 생성과 보고서 버전 보존

기본 RA 도우미는 로컬 규칙 기반입니다. 외부 AI 어댑터 구조와 실제 공급자 연동·검증은 구분합니다.

## 🩻 Brain MRI

### MRI 3D 시각화·마스크 기반 부피 측정 프로토타입

[![Repository](https://img.shields.io/badge/GitHub-mri-181717?style=flat-square&logo=github)](https://github.com/junhaj27-jpg/mri)

DICOM·NIfTI 기반 MRI 데이터를 불러와 2D 슬라이스와 마스크 기반 3D 모델을 확인하는 연구용 웹 프로토타입입니다.

**MRI 로딩 → 전처리 → 마스크 처리 → 부피 계산 → 3D 메시 생성 → 시각화·보고서**

NeuroAge-MAS의 표 형식 연구 분석과 별도로, 원본 의료영상의 로딩·공간 정보·마스크·시각화 과정을 다룹니다.

### 주요 구현

#### 1. 의료영상 로딩

- DICOM 시리즈 탐색과 볼륨 구성
- NIfTI 영상·마스크 로딩
- 영상 배열·affine·voxel spacing·메타데이터 관리
- NIfTI 방향 표준화와 분석용 데이터 저장

#### 2. 전처리와 2D 뷰어

- 백분위수 기반 영상 강도 클리핑·정규화
- Axial·Coronal·Sagittal 슬라이스 추출
- 마스크 오버레이 시각화
- 브라우저에서 슬라이스와 처리 상태 확인

#### 3. 마스크 처리와 품질 점검

- 뇌 추출 도구 실행 연계와 결과 마스크 로딩
- 연결 요소·경계 접촉 등 마스크 품질 진단
- 신뢰 가능한 처리 결과와 임계값 기반 디버그 결과 구분
- 마스크 상태에 따른 최종 3D 생성 제한

#### 4. 부피 계산

- 마스크 voxel 수와 voxel 크기를 이용한 부피 계산
- 영역 labelmap 기반 영역별 부피 집계
- 결과 CSV 내보내기

**부피(cm³) = 마스크 voxel 수 × voxel 부피(mm³) ÷ 1,000**

부피 결과는 입력 마스크와 spacing 정보의 정확성에 영향을 받습니다.

#### 5. 3D 메시와 보고서

- Marching Cubes 기반 표면 추출
- 다운샘플링·평활화와 메시 후처리
- 연결 요소와 메시 품질 점검
- GLB·STL 내보내기
- Three.js·Plotly 기반 시각화
- 슬라이스·마스크·부피 결과를 포함한 PDF 생성
